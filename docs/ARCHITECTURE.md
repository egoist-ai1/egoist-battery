# Архитектура

## Границы слоёв

`EgoistBattery.Core` содержит модели, парсеры, объединение результатов (merger) и `TrayPolicy`; этот проект не зависит от WPF. Windows-провайдеры получают данные из системных и аппаратных источников и передают их в общий слой обработки.

Каждый источник опрашивается изолированно, чтобы его задержка или ошибка не останавливала остальные. Опрос координируется одним `Semaphore` с общим бюджетом 20 секунд. Для HID-запросов отводится до 650 мс, для запроса Logitech — 350 мс.

## Источники и данные

Провайдеры читают доступные данные DualSense и DualShock 4 через USB/Bluetooth HID, Logitech через HID++ 2 GET1004/1000, Windows PnP HFP battery cache, уже подключённые BLE-устройства с Battery Service 180F и характеристикой 2A19, XInput и батарею компьютера. BLE-обнаружение не подключает устройства. Для Sony не отправляет HID output/feature reports. Для Logitech HID++ отправляет только GET-запросы доступных функций, имени, типа и батареи; SET отсутствует.

Merger объединяет сведения по стабильным физическим идентификаторам устройств, сохраняя источник и время получения данных, если они доступны. Полный JSON-снимок записывается атомарно при изменении данных либо при очередном опросе после пяти минут без записи, чтобы читатель не получил частично записанный файл.

## Жизненный цикл

Монитор работает в основном процессе и остаётся единственным владельцем аппаратных провайдеров. Экономный режим включён по умолчанию: фоновый опрос идёт не чаще одного раза в 60 секунд; пока окно открыто, по умолчанию — каждые 15 секунд. Изменения USB/Bluetooth и возобновление после сна дебаунсятся 800 мс. Фоновый процесс сам не строит окно и карточки. Системные уведомления принимает невидимое `DeviceEventWindow` на базе `System.Windows.Forms.NativeWindow`.

По запросу основного процесса запускается дочерний процесс того же EXE с параметром `--window`. В нём создаются WPF-окно и карточки; его `SnapshotDeviceSource` читает атомарный `last-snapshot.json` и не опрашивает HID или GATT. Именованные события `Local` передают запросы на обновление снимка, перечитывание настроек, активацию и завершение окна. Кнопка обновления сигнализирует единственному фоновому `DeviceMonitor`; параллельного аппаратного опроса из процесса окна нет. Окно сохраняет изменения настроек и сигнализирует монитору; монитор перечитывает их без обратной записи. Закрытие или сворачивание завершает процесс окна, а монитор и значки трея продолжают работать. При завершении монитора процесс окна закрывается по событию и по наблюдению `Parent.Exited`.

`Mutex` основного процесса и отдельный `Mutex` процесса окна не дают запустить дублирующие экземпляры. Значки трея формируются через GDI+ контуры `GraphicsPath`; кэш `RenderKey` пропускает повторную отрисовку, пока не меняются значение, процент, состояние, палитра панели задач или размер значка по DPI. Нативные дескрипторы закрываются при завершении соответствующей операции.
